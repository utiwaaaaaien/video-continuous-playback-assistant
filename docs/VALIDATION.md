# V3.1 验证记录

日期：2026-10-06。扩展3.1.0；Mac组件2.1.0。

## 自动化回归

135项测试全部通过，覆盖内容脚本和后台。真实两分钟等待由虚拟时钟加速，跨刷新创建新文档并从持久会话恢复。

- 人工问题120秒前不刷新，到期最多刷新一次，刷新后最多60秒核验；视频真实时间前进才算恢复，单独playing事件不算成功。
- 可信点击、按键、输入和通知点击取消倒计时；合成点击不算反馈。停止、导航、关闭标签取消旧计划。
- 答题、验证码刷新一次且不自动作答或提交；刷新后失败进入人工处理并请求Chrome通知。
- 网络在第2、4、6分钟刷新，第三次核验30秒后停止、释放保护并请求通知；恢复则取消余下计划。离线无内容脚本时后台仍按原次数继续。
- 会话保存失败不执行刷新；旧文档写入不能重置已刷新标记；页面与后台同时到期只刷新一次，后续请求返回已执行状态。
- 刷新调用失败或通知接口不可用时保留人工状态，避免无限循环。
- 补充网站主机权限，供后台读取标签地址；内容脚本仍限定播放页，未增加全站tabs权限。
- 保留既有补播、跨课程、全一集、完成标记、中央播放按钮、状态灯与多标签唤醒隔离回归。

测试命令：Node内置测试运行器执行tests/*.test.cjs。

## 当前Chrome实测

当前Chrome扩展已加载V3.1，原ID保持不变。首次计时实测发现后台无法读取标签地址，已按Chrome官方权限说明补齐该网站host_permissions，并增加配置回归测试。另处理后台先刷新、页面随后请求的并发场景，防止误报失败。

复测临时关闭“自动确认”并启用连续播放，用真实网站欢迎提示产生人工问题。工具栏显示02:00倒计时；两分钟后出现“已刷新一次 · 正在核验播放”，新文档记录在23:40:54重新识别提示，23:40:58识别播放器。23:41:53进入“自动刷新后仍未恢复播放”的人工状态，倒计时结束，没有启动第二次刷新。人工提醒及通知调用路径通过自动化验证，未单独确认macOS横幅实际展示。

随后恢复自动确认并点击“已处理，继续”。欢迎提示自动关闭，已完成的“全一集”课程自动进入下一课程（仍为“全一集”）。新视频从0%正常播放，面板绿灯，浏览器与Mac本地保护均确认；收起面板后播放时间继续增长。测试创建的扩展管理标签已关闭。
