# 视频连续播放助手 V3.1

本地 Chrome 扩展，适用于 macOS 上中国教育干部网络学院课程播放页：`https://estudy.enaea.edu.cn/web/player/*`。

## 安装与更新

1. 解压 V3.1 发布包，保留解压后的文件夹。
2. Chrome 地址栏打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的 `course-player-assistant` 文件夹。
4. 返回已登录的课程播放页，刷新页面。

已安装旧版本时，将原安装目录中的文件替换为 V3.1 文件，点击该扩展卡片的“重新加载”，再刷新课程页。重新加载扩展后，请刷新课程页面并检查连续播放是否开启。

扩展显示版本 V3.1，Chrome 数字版本为 3.1.0，符合 [Chrome 版本规则](https://developer.chrome.com/docs/extensions/reference/manifest/version)。安装无需 Node.js、编译或服务端。

## 使用与播放规则

1. 打开课程，点击“开始连续播放”。未完成的首集可以先在网页中手动播放。
2. 未完成集按目录顺序继续播放，已经显示“完成”或“已完成”的集数自动跳过。
3. 播放到目录末尾后，如果仍有未完成集数，助手回到最早的未完成集自动补播，随后继续按目录顺序处理剩余集数。
4. 当前集一旦显示“完成”，就无需听到视频结尾。全目录都显示完成时，直接进入下一个课程；即使播放条才走到 90% 多，也不会继续重听。跳转前保留约 1.6 秒以协调网站自身的切集。
5. 如果视频已结束，但当前集仍显示 90% 多或其他百分比，助手继续补播。只剩当前集时，先等待最多 20 秒，让完成标记更新，再重选该集。补播从网站提供的位置开始。
6. “目录全部完成后进入下一个课程”默认开启。关闭后仍会跳过已完成集和补播漏播集，目录全部完成后结束本次连续播放。
7. 已识别的继续播放提示和固定欢迎提示可以自动确认；欢迎提示只点击“知道了”，不修改“今日不再提示”偏好。答题、验证和未知弹窗交给你处理，完成后点击“已处理，继续”。
8. 点击“停止连续播放”取消排队中的自动操作。面板收起后仍显示实时播放条、目录百分比、插件状态和唤醒状态，扩展工具栏也可查看和控制。

如果网站目录在连续三次补播后仍未更新进度，助手提示人工检查，避免无限重听。自动播放被浏览器拒绝、入口不明确、加载超时或跳转循环时也会显示处理提示。

## V2.2：保持唤醒与本地组件

开启连续播放和“播放时保持 Mac 唤醒”后，助手在实际播放、短暂缓冲及受控切换期间保持保护；显式暂停、停止、答题或会话结束时释放。后台每 30 秒探测播放状态，页面每 15 秒报告；浏览器租期为 120 秒，过期后清理，实际时机受 Chrome 调度影响。

Chrome 的 `display` 电源请求负责阻止闲置睡眠；本地组件补充 macOS IOKit 电源断言和活动声明，处理独立屏保的闲置计时。依据 [Chrome power 接口](https://developer.chrome.com/docs/extensions/reference/api/power) 和 [Apple IOPMAssertionDeclareUserActivity](https://developer.apple.com/documentation/iokit/1557179-iopmassertiondeclareuseractivity)。

首次使用本地保护：加载扩展后，在 chrome://extensions 复制扩展 ID，运行发布包 mac-wake-helper 中的“安装Mac唤醒组件.command”，粘贴 ID。组件复制到当前用户 Application Support，通过 Chrome Native Messaging 启动。无需管理员权限、辅助功能权限或文稿访问权限。详见同包 mac-wake-helper/README.md。

面板收到组件确认后显示“Mac 本地保护 + 浏览器保护”。未连接时只显示浏览器保护；连续三次连接失败后停止自动重试，修复安装后关闭再开启唤醒开关即可重试。组件使用 75 秒租期，断连、停止、锁屏或超时后释放。不会修改系统锁屏设置，也不自动解锁；手动锁屏、合盖和企业策略仍由系统处理。

已实测建立与释放系统请求，以及 Chrome 与组件的连接。尚未完成超过系统屏保阈值的无人操作耐久测试，不能承诺所有闲置锁屏场景均已解决。

中央播放按钮修复按视频真实状态生效：媒体播放时隐藏该网站 xgplayer 的中央启动按钮，暂停、结束、换源或视频元素替换时恢复网站自身显示规则；暂停后仍可点击中央按钮继续。该修复即使连续播放尚未开启也生效，仅匹配当前播放器的 `xg-start.xgplayer-start`，不会隐藏工具栏、缓冲指示或答题弹窗。

## 两类进度

页面面板和扩展工具栏同时显示：

- 播放条：当前播放时间 / 总时长，以及按时间计算的播放百分比。
- 目录：当前集的百分比或“完成”，以及当前目录已完成集数 / 总集数。

这两类进度可能不同。是否还需要听这一集，以目录明确的“完成”标记为准；单独出现 100% 数字仍要等待完成标记。播放条时间只用于显示，不替代网站完成状态。

技术上使用标准媒体元素的 [currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime) 和 [duration](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration) 读取时间，独立读取目录进度区域。页面面板随播放和目录变化更新，工具栏约每 1.5 秒更新。

## 会话与支持范围

状态按标签页保存，同课程刷新可恢复。助手发起的跨课程跳转只在同一项目、学习活动和学习计划内接续；关闭标签页、重启 Chrome、更新或重新加载扩展后，请刷新课程页面并检查启用状态。自行切换课程也需重新启用助手。

当前版本只适配上述网站。网站结构改版可能需要更新；浏览器原生确认框及未适配组件需手动处理。真实网站的周期性继续确认和答题弹窗尚未出现，当前相关规则已通过模拟测试。

## 权限与数据

内容脚本只匹配该网站播放页。声明该网站的主机权限，以读取当前标签地址并核对自动刷新的课程和视频；页面操作仍只在播放页执行。`storage` 保存当前标签页会话状态，`notifications` 发送人工处理提醒，`power` 临时保持电脑与屏幕唤醒，`alarms` 探测播放状态并清理过期请求，`nativeMessaging` 仅连接本地唤醒组件。扩展不调用外部服务，网站继续管理登录状态和学习记录。系统通知受 macOS 和 Chrome 设置影响，页面提示始终保留。

助手只读取进度并操作普通页面控件，不设置播放器时间、修改服务器完成状态或题目答案。

## 文件与验证

`manifest.json` 为入口；`content.js` 处理页面交互；`core.js` 处理判断规则；`background.js` 保存会话并提醒；`ui.js` 为共享界面，`popup.*` 为工具栏界面。发布包可直接加载，不包含测试依赖。

验证结果见 `TEST-REPORT.md`，更新说明见 `RELEASE-NOTES.md`。在 `chrome://extensions` 中可停用或移除扩展。

## V2.2：切换与界面

切换前保存目标，点击后确认新的媒体真正加载，避免只看到目录选中项变化就误判成功。目标未响应时最多点击三次；一旦媒体或课程开始变化即停止重复点击，避免连跳。切集等待最多 45 秒，跨课程最多 60 秒；新媒体与新目录都准备好后才继续。

界面参考 [Apple WWDC26 macOS 27 AppKit 设计](https://developer.apple.com/videos/play/wwdc2026/289/)，采用系统字体、玻璃材质、同心圆角、蓝色控件、深浅模式，以及减少透明度和动态效果支持。

## V2.2：跳转后自动恢复

目录识别依据该网站的标题、进度和选中标记，不再要求标题以“第几集”开头，支持“课程名01.mp4”等文件名和普通标题。保留目录顺序及网站“完成”标记作为切换依据。

对已识别的欢迎/继续播放提示，点击后每 250 毫秒检查实际活动弹窗，最多等待 8 秒，并在仍可操作时最多确认三次。透明、隐藏或被替换的旧弹窗不再阻断后续流程。提示关闭后重新核验目录和视频，自动接续播放。出现答题、验证或未知弹窗时仍提示人工处理。

从 V2.1 升级无需重新安装 Mac 组件。该组件继续使用 2.1.0，扩展显示 V3.1（3.1.0）。

## V2.5：状态灯与网络重试

展开、收起及工具栏界面都显示红黄绿三个灯，并点亮当前状态。状态灯位于标题栏右侧、收起/展开按钮旁，与左侧图标和介绍垂直居中对齐；不显示灯后的文字备注：

- 绿灯：助手启用、视频真实播放、自动确认/跨课程/保持唤醒均开启，且本地与浏览器保护都已确认。
- 黄灯：正在播放，但部分选项关闭，或唤醒保护未就绪。
- 红灯：没有播放、助手未启用、暂停、等待人工处理或等待网络重试。

网络错误包括媒体网络错误、断网导致的媒体错误，以及播放器明确的网络错误/连接超时提示。解码错误、答题或自动播放授权错误不会按网络故障盲目刷新。

发生网络错误后，在第2、4、6分钟刷新当前播放页重试，累计最多三次。次数和目标按标签保存，刷新不会重置。页面离线错误时由后台继续调度。每次刷新后最多等待30秒，通过真实播放时间前进判定恢复；最后一次最多到第6分30秒完成核验。Chrome的后台调度、系统睡眠可能使实际执行延迟，不承诺精确到秒。

网站自行恢复或重试成功后取消剩余任务并继续播放；停止助手、遇到答题、换课程或换集会取消原计划。重试期间若保持唤醒开关开启则继续保护；第三次仍失败时停止本标签播放、关闭本次助手并释放唤醒。按用户确认，随后由现有 macOS 系统设置自动锁屏，不立即强制锁屏，锁屏时间以系统配置为准。如果其他标签仍正常播放，保留它们的保护。

采用 [Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms) 辅助调度和 [Chrome power](https://developer.chrome.com/docs/extensions/reference/api/power) 管理保护。本版沿用已安装的 Mac 组件，不需要新增辅助功能权限。

## V2.6：圆角与排版修正

外层浮窗透明且不裁切阴影；背景、边框、圆角和滚动均由内部卡片管理，避免四角阴影出现直角裁切。外层清除网站可能施加的背景、边框、阴影和滤镜。面板采用24px圆角、按钮12px圆角、设置分组16px圆角，并统一文字粗细、标题版本间距和水平内边距。

窄窗口中的标题以省略号收尾，状态灯和展开按钮保持可见；矮窗口在卡片内部滚动，保留四角形状。实际UI代码的浅/深色、展开/收起预览和320×480布局均已检查。当前Chrome已更新到V2.6并恢复播放。

## V3.0：不依赖集号的跨课程播放

按目录实际显示的完成状态处理：目录还有未完成视频时继续顺序播放和补播，全部显示“完成”后点击网站的“下一个课程”并自动播放。仅显示100%仍不等同于网站“完成”标记。

跨课程不再要求新旧目录标题不同。连续两个课程都叫“全一集”、目录使用普通名称或文件名时，使用课程地址、媒体来源/加载状态、目录节点或进度更新确认新课程已就绪。单视频目录缺少选中标记时可自动确定当前视频；多视频选中状态有歧义时提示检查。

旧完成目录残留期间先等待目录更新，防止把新课程误认为已完成而连续跳过。欢迎和普通继续提示自动确认；题目仍等待用户完成。

## V3.1：自动刷新恢复与通知

连续播放启用时，播放失败或进入人工处理状态后开始2分钟倒计时。期间在课程页面点击、按键、输入，或点击浏览器通知，即视为用户反馈，取消本次自动刷新。点击“停止连续播放”、切换课程或视频同样取消计划。

无人操作时自动刷新当前播放页一次。刷新后最多核验60秒，确认目录已识别、阻断提示已消失且视频时间真实前进后继续正常播放。仍不能恢复时保留人工处理状态并发送Chrome通知，不再反复刷新；处理后点击“已处理，继续”或重新开启助手。

答题、验证码和未知弹窗也按用户选择刷新一次，刷新可能丢失未提交的输入；助手不自动答题或完成验证码。主动暂停不会触发该恢复计划。跨项目异常和课程循环等保护性停止需要人工检查。

网络错误采用独立规则：每2分钟刷新一次，最多3次，每次最多核验30秒。恢复后取消剩余计划；3次失败后停止本标签、通知用户并释放该标签的唤醒保护，由系统按现有设置自动锁屏。其他正常播放标签的保护保留。切换为答题等人工问题时取消原网络计划，改用一次刷新规则。

刷新次数和截止时间保存在当前标签会话中，防止刷新重置次数。后台定时辅助处理离线错误页，实际执行仍受Chrome调度及系统睡眠影响。系统通知是否显示受macOS及Chrome通知设置影响，页面处理提示始终保留。
